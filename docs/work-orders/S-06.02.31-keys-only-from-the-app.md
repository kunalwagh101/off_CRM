# Work order — S-06.02.31 provider keys come only from the app

## ID
S-06.02.31. Fixes `D-151`. Decision `DD-64`. Size S.

## GOAL
A provider key is one somebody typed into Connectors for that workspace. The
server's environment supplies none, and a connect with no key is refused with
the next step — except a local server that needs no key.

## BLAST RADIUS
- `ai/workspace.py::key_for` — the `OFFSETX_AI_<PROVIDER>_KEY` fallback; used by
  `has_key` on every provider row and by the broker's `credential_resolver`.
- `ai/workspace.py::connect_provider` — connects with no key today.
- `ai/failures.py` — the AUTH owner action tells people to set the variable.
- Docs naming the variable: `AGENTS.md`, `docs/architecture/FAILURES.md`,
  `docs/architecture/REBUILD_GUIDE.md`.
- Not touched: `broker._instantiate`'s `env_name` — a label inside a private
  dictionary handed to the adapter, never a read of `os.environ`.

## TEST (write first, watch it fail)
1. With the variable set, every workspace's `key_for` is empty and the provider
   list says `has_key: false`.
2. Connecting a keyed provider with a blank key and none stored answers 400 with
   a sentence that says to paste the key; nothing is stored.
3. Connecting `local` (needs no key) with a blank key still works.
4. The AUTH owner action no longer mentions an environment variable.

## DONE WHEN
The tests pass through the API, the docs no longer offer the variable, and a
real browser connect with no key shows the sentence.
