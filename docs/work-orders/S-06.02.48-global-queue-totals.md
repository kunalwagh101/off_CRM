# S-06.02.48 — Queue totals represent the full campaign

**State:** IN_REVIEW, not verified in a production runtime.

## User story
As a campaign owner I need the Send Queue's Ready, Needs approval and Replies counters to represent the entire campaign, not the visible page.

## Acceptance
- Given 211 queue members and a 10-item page, when I read the summary, then Ready, Needs approval and Replied counts reflect all 211.
- Given a future scheduled-at timestamp, when now is before it, then that approved draft is not counted as due/ready.
- Given a replied, completed or stopped contact, then it is not counted as a ready or needs-approval candidate; replied is counted separately.
- Given a different page or view, then the same campaign-level counts remain available.

## Definitions
`ready` means a nonterminal contact with an approved, sendable draft and an effective due timestamp at/before now. It is **not permission to send**: provider preflight, valid email, suppression, send window, quota, and actual sender checks still apply. `approval` means nonterminal and due without an approved draft (including missing). `replied` is status replied.

## Implementation
`OutreachStore.send_queue_view` applies the same timezone-aware `parse_datetime` rule as the sender across lightweight control rows. API carries `counts: { all, ready, approval, replied }` separately from page `total`. The existing UI stat cards use these counts. Tests use large populated CRM and future timestamps.

## Required gates
Python suite, frontend Vitest/build, real local and PostgreSQL clock-offset/scheduling acceptance, and browser verification. No live send or integration was made in this session. No schema changes. Roll back `send_queue_view`/API/UI together; the sender stays untouched.
