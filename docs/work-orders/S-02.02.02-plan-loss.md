# Work order — S-02.02.02 do not regenerate a lost managed PLAN.md

## ID
S-02.02.02 — PLAN.md as the single source of truth. CHECK-mode defect repair.

## GOAL
Once a run has been managed by S-02.02.02, losing PLAN.md must stop the run.
A restart/resume must never recreate the original plan and erase owner steering.

## ROOT CAUSE
`AgentRun.run()` always calls `RunPlan.ensure(goal)`, including resume.
`ensure()` cannot currently distinguish:
- a legacy pre-S-02.02.02 run that genuinely never had PLAN.md; from
- a managed run whose PLAN.md was deleted after the owner edited it.

Both cases recreate PLAN.md from the original goal.

## FILES
MODIFY:
- tests/test_agent_plan.py

- docs/architecture/AGENT_PLAN.md
- DEFECT_LOG.md

DO NOT TOUCH:
- trace step numbering or trace schema
- resume budget/spend/latency semantics
- browser action loop
- PLAN.md content format
- owner goal normalization
- S-02.02.03 interrupt/steer/resume scope

## TEST
1. create a managed RunPlan;
2. replace its content with an owner edit;
3. delete PLAN.md;
4. call `ensure()` as the resume path does;
5. require `PlanError` instead of a regenerated plan.

Keep the existing legacy case: a directory that genuinely predates PLAN.md can
receive one on first managed resume.

## FIX
Create a private non-content marker beside PLAN.md once the directory is under
RunPlan management. The marker is not a second plan; it stores no instructions.

- existing PLAN.md + no marker: validate the plan and add the marker (migration);
- no PLAN.md + no marker: create the first plan and marker (new/legacy);
- marker + missing PLAN.md: fail closed;
- marker + present PLAN.md: read it exactly as today.

## DONE WHEN
A restart cannot silently replace an owner-edited plan with the original goal,
legacy runs remain compatible, and the model still reads PLAN.md fresh before
every decision.
