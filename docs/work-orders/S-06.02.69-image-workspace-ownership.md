# S-06.02.69 — Image briefs, assets and video handoff respect workspace ownership (A05)

Status: BACKLOG, security build-ahead during production audit S-06.02.23 IN_PROGRESS. Work on develop only.

## Problem
ImageStore already writes immutable workspace_id for image_briefs and image_assets, but image endpoints and ImageCampaignEngine use global IDs or campaign-only list queries. CRM campaign tenancy is undecided (Q-27), so a common campaign does not make its images public to every workspace. A workspace may read another's image bytes, brief text, review queue, and generator result, or approve/reject and delete a peer's file. VideoEditorEngine also receives a global image-store asset_reader and approved-asset query for the same campaign, creating cross-workspace video placement/assembly risk.

## Acceptance
- Two real cookie-authenticated workspace sessions share a synthetic CRM image campaign. Each sees only its own briefs/assets/queue/summary; database SQL filters workspace before any ordering/limit. Empty lists and 404s do not expose foreign filenames or workspace IDs.
- Foreign asset /file URL returns 404 without private image bytes, even when the asset ID is known. Owner can still download own pending or approved asset.
- Foreign brief ID /generate refuses with 404 before any AI provider/broker call, with no generator usage, file or score change.
- Foreign image ID /decide approve, reject or regenerate refuses with 404 before file deletion, status mutation or scoring. Owner's local swipe path still updates its own status.
- Video place-asset and automatic / explicit assembly cannot use another workspace's approved picture, even when campaign ID matches.
- No CRM tenancy migration, schema changes, external provider calls or customer data. Preserve existing local workspace and isolated ImageStore callers.
- TDD RED on isolated Render, GREEN focused and complete SQLite/PostgreSQL suites, Chromium, frontend, static, concurrency and structural board checks. Independent penetration, real customer acceptance and full Git-history verifier remain open.

## Design
Implement owned-brief and owned-asset checks in ImageCampaignEngine before generation, decisions or delete. Add optional workspace_id SQL WHERE to ImageStore list_briefs/list_assets (existing independent call signatures remain compatible). API passes actual authenticated workspace to image lists and direct download. Video image asset_reader validates workspace and approved campaign asset list is SQL-scoped; preserve release policy and existing video workspace protections.
