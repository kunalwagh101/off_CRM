# Work order — S-04.01.02 Agent playbooks loaded only when selected

## Goal
Companion agents keep reusable procedures separate from remembered facts. A procedure irrelevant to a run is absent from that run's model-visible prompt and egress log; selecting a permitted procedure attaches only its bounded approved text. This is a customer-facing application capability, not a development-agent skill installer.

## Read and preserve
`AGENTS.md`, `offsetx_apollo_builder/agent/companions.py`, `offsetx_apollo_builder/agent/run.py`, `offsetx_apollo_builder/api/app.py`, `offsetx_apollo_builder/ai/broker.py`, `tests/test_agent_companions.py`, `tests/test_agent_run.py`. Keep workspace authentication, tool permissions, memory scopes, trust tiers and provider egress scanning intact. Reuse existing companion storage and lifecycle; do not add a second broker or an unrestricted file-reading tool.

## Readiness
`S-04.01.01` is still IN_REVIEW. **Q-30 was answered2026-11-05:** only explicit owner-authorised procedure IDs select bounded text; no page or model automatic selection. Do not silently widen prompts or let untrusted page text activate a skill. This story stays in BACKLOG pending the upstream DONE gate and complete acceptance evidence.

## Testable acceptance
1. Persist two bounded procedures under separate workspace IDs. A run that selects none sends neither procedure; a run selecting one includes only the authorised procedure. Assert on the actual constructed broker request, not a mock claim about output.
2. Cross-workspace, deleted/disabled, oversized or unknown procedure IDs fail before a provider call. No arbitrary filesystem path, network fetch, executable code or secret-bearing metadata is accepted as a procedure.
3. Restart the server and verify procedures persist in the install's real storage topology. Deleting a procedure makes a previously selected ID fail closed; record clear recovery guidance. Keep memory/facts separate from the procedure record, with no implicit recall.
4. Through the authenticated companion UI/API path, owner can see selected procedure, enable/disable or remove it, and observe the effect on the *next* run without stale prompt caching. Existing companion run and egress tests remain green.

Remain IN_REVIEW until cross-workspace, persistence and live prompt evidence is executed.
