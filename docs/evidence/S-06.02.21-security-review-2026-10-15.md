## Confirmed security defect D-313

The shared CRM engine's linked-product reader in `offsetx_apollo_builder/api/app.py` checked `_CALLER_WORKSPACE.get()`. Its default was `None` and that was interpreted as an installation timer with permission to read any linked workspace product. A bare thread, lost request context, or a caller that bypassed request middleware therefore gained that authority. This is material because campaigns and drafts are install-wide while products belong to individual workspaces.

**RED first:** `tests/test_workspace_isolation.py::test_lost_request_context_cannot_read_other_workspaces_product` was added first. Render isolated QA runner `dep-db8cjmajnfac73f52o2g` ran `uv run pytest -q tests/test_workspace_isolation.py::test_lost_request_context_cannot_read_other_workspaces_product` on the old code: **1 failed as expected**, proving that the product reader did not deny missing context. This is a behavioural reproduction, not an import error.

**Fix:** `_CALLER_WORKSPACE` now defaults to empty unauthenticated context (`""`) and only an explicitly authorised content automation timer may set the privileged `None` value. `_install_content_scope()` sets and resets the token in a finally block. The timer's scope is injected into `ContentAutomationService` and is applied to the actual `asyncio.to_thread` execution, which propagates the context into the worker. The owner's manual timer action uses the same scope after `require_install_owner` passes. A separate new regression verifies the timer can access the linked product and scope resets afterward. Decision: `DD-121`.
