# S-06.02.63 — Token-authenticated media (audit A20)

## Scope
Fix F-06.02 A20: audio and footage loaders, still-image decoding, image review and editor thumbnails must use authenticated binary access in token-only installs while retaining cookie-login support. A denied resource cannot be mistaken for a missing asset. No bearer tokens in URLs or cross-origin requests.

## Acceptance (test-first)
- Token mode attaches Authorization Bearer and credentials to same-origin private image, audio and video requests.
- Cookie mode sends credentials without bearer headers.
- 401 and 403 produce an actionable authentication or permission failure; a true 404 remains missing.
- An untrusted URL can never receive an API token.
- Token-only anonymous /auth/session is unauthenticated, and a verified token may access the dashboard.
- Browser object URLs are revoked on unmount/token changes and never persisted.
