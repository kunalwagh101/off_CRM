# S-06.02.50 — Enforce a configured limit on video-media and render uploads (A15)

**Feature:** F-06.02 production reliability and security. **Owner authorised next development feature 2026-10-30**, existing A15 audit remediation; current story in IN_REVIEW after source and tests authored.

## User outcome
The server refuses video-media and rendered-video multipart bodies that exceed the install's configured `OFFSETX_MAX_UPLOAD_BYTES`. Both endpoints check bytes before invoking media probes or writes. Empty files are refused; valid files below the limit remain usable. API authentication remains mandatory.

## TDD and acceptance
- Given max upload 2048 bytes, when either endpoint receives a 6000-byte file, then HTTP 413 is returned, no video is stored, the byte reader uses a bounded `read(2049)`, and a repeated rejection does not affect later requests.
- Given a copied/malformed Content-Length claim, the actual file bytes are still checked.
- Given an unauthenticated or empty request, it fails with 401 or 400 without video persistence.
- Given a real WebM below the configured limit, it imports and is listed by the same authenticated API.
- Existing video render and imports and AI egress/security regression must remain green.

**File scope:** `offsetx_apollo_builder/api/app.py`, `tests/test_video_upload_security.py`. Reuse existing AppSettings and no new dependencies or schema. Do not alter S-06.02.23 audit's prohibition on editing application code as part of the *audit recheck*; this is a distinct remediation item.

## Execution and outstanding limits
Pre-code source reproduction (minimal FastAPI app mirroring current `await file.read()`) accepted a 4096-byte upload with 201; this is a mechanism reproduction, not a run against the full off_CRM app. Full regression on Render is mandatory before source verification is claimed.

**Remaining A15 production gaps:** multipart parsing/spooling occurs **before** endpoint function runs, so a giant chunked body can consume disk; a configured request-stream maximum and upload concurrency quota are still required, along with disk/memory measurement, interruption cleanup and video-file streaming/decoding. **Do not mark A15 CLOSED or S-06.02.50 DONE** based on this bound alone. No provider keys and no customer data should be sent.

## Recovery / rollback
No schema changes. Revert this handler change to restore previous upload behaviour, but that would re-open A15; use a bounded configured upload budget instead. Changing the environment cap affects other upload routes as well, so adjust it only with an operator-approved resource budget. Test real WebM acceptance before merging.
