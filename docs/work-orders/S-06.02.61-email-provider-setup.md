# S-06.02.61 — Provider setup cannot strand an email delivery job (A16 / D-363)

Status: BACKLOG. Do not pull while S-06.02.23 is IN_PROGRESS. Branch: develop.

## Proven current-source gap
The original A16 audit reproduced an email job stuck in sending after a provider factory raised. On 2026-11-03, \`EmailDeliveryService._send_job\` still calls \`self.provider_factory(job, identity)\` before its \`try: provider.send_message\` block. The catches for permanent, retryable, ambiguous and unexpected errors therefore do not handle a setup error. This is a source recheck, not a fresh worker/SES integration test.

## Acceptance (test-first, no actual customer email)
1. **Given** a previously claimed queued mail job, **when** provider creation raises a known permanent error before transport, **then** its state becomes terminal failed or blocked, the worker returns an actionable reference and no recipient receives a message.
2. **Given** a temporary provider setup error, **when** its classification permits retry, **then** the worker schedules a bounded retry and retains the exact job identity; no ambiguous-sent state is created before transport.
3. **Given** unknown setup failure or missing credentials, **when** provider creation fails, **then** the job cannot remain forever in sending and another unrelated due job still executes. No raw credential or recipient content reaches logs.
4. **Given** a worker restart after setup failure, **when** it resumes, **then** it cannot double-send or silently change an explicit terminal/blocked state.
5. **Given** a provider error thrown *after transport begins*, **when** send outcome is genuinely uncertain, **then** the existing quarantine/do-not-resend protection remains intact.

## Implementation
Write an A16 named regression through the existing \`EmailDeliveryService.work_once\` and real store first; run it RED in isolated QA. Move provider acquisition into the pre-send classified error boundary, without widening the exception scope to incorrectly mark post-send uncertainty as definitely unsent. Preserve max attempts, idempotency and one error reference per failure. Keep the existing adapter contract. Avoid new dependencies.

## Gates
Focused test, full deliverability and provider fault tests, security/no-leak and restart tests, SQLite and real disposable PostgreSQL, integration and worker concurrency gates, full regression, Ruff, frontend and Chromium impact, full board verifier. Manual owned sandbox/SES acceptance still separate. Roll back only if worker claims and last-safe-state proof survives. No main/customer sends or promotion.
