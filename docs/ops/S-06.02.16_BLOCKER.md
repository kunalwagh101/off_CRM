# S-06.02.16 — frontend dependency audit blocker

Status: externally blocked on 2026-09-17. This is not DONE evidence.

## What was reproduced from the repository

The current frontend lockfile resolves these development-only vulnerable copies:

- `nanoid@3.3.16` (transitive through the frontend tooling graph).
- `vitest@4.1.10` and its matching `@vitest/*@4.1.10` family.

The production dependency set is only React/React DOM; the previously recorded
`npm audit --omit=dev` result was clean. D-47 remains open until a clean install
re-runs both production and full-tree audit checks after remediation.

## Remediation boundary

Do not use `npm audit fix --force` and do not hand-edit a manifest without a
matching lockfile. The minimum non-breaking remediation to verify is:

1. Refresh the 3.x `nanoid` resolution to a patched release (at least `3.3.18`).
2. Raise `vitest` from `4.1.10` to at least `4.1.11`, keeping its matching
   `@vitest/*` packages on the same patch line through a normal npm lock refresh.
3. Run a clean `npm ci`, not an install over an existing tree.

## Why certification stopped

GitHub Actions run `35198922432` (`s060216-frontend-audit-once`) failed twice
before executing any step. Attempt 2 job `105129090155` reports `steps: []`,
`runner_id: 0`, and an empty runner name. The normal repository CI on the same
branch also failed before executing any step. That is an external runner/account
condition, not test evidence about the code.

The temporary audit workflow was removed after the failed probe so no one-shot
workflow remains in the branch.

## Evidence required before DONE

From `frontend/` on Node 24 with network access:

```bash
npm ci
npm audit --omit=dev
npm audit
npm test
npm run build
```

Required results:

- production audit: zero vulnerabilities;
- full development audit: zero unresolved high-severity findings;
- frontend tests: all pass;
- production build: succeeds.

Then run the repository-wide gates from the repository root:

```bash
uv sync --extra dev --extra email --locked
uv run pytest -q
uv run python scripts/verify_board.py
```

Only after all of those pass should D-47 be closed and S-06.02.16 move to DONE.
