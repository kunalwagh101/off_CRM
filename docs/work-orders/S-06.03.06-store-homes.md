## Test-first acceptance

1. For each store, construct real user-owned state through its application boundary and save it. Tear down the service and delete the disposable folder; rebuild with the same hosted DB; state must survive, with no data mixed between workspaces.
2. Simulate a database outage, malformed snapshot, conflicting local state, concurrent writers and interrupted migration. No false success, lost consent, duplicate external effect, secret in error response or unlogged failure. Log IDs match user-visible references.
3. Restore into a disposable new PostgreSQL, reconcile record counts and repeat each write. Prove rollback preserves the source. Never restore over an actual running customer database.
4. Every store classified disposable must have evidence of informed user consent and a visible warning at every affected screen. No business-critical consent, tokens or unsent queue may be classified disposable by a developer shortcut.
5. `GET /api/v1/storage/readiness`, the generated inventory table, production startup guard and their tests must agree. A hosted CRM and timer documents alone are not sufficient for production status.
6. Run targeted unit/integration/security regressions, actual process restart, full `uv run pytest -q` with SQLite and disposable PostgreSQL, Chromium desktop/mobile, Ruff, frontend tests/build/audit and `uv run python scripts/verify_board.py`. ## 2026-11-05 — Archive-first companion cutover (implementation unverified)

The owner-approved, existing HostedStorage SQL backend now holds companion
profiles and manually selected procedures on hosted installs. It DOES NOT
replace the executable tool registry (ai_tools.db) or make tool grants durable.
A hosted boot refuses to silently ignore differing local companion rows.

New operator-only CLI:
    
    uv run offsetx-db import-companions \
      --source /old/private/data/ai_tools.db \
      --archive /durable/private/archive/ai_tools-before-hosting.sqlite \
      --yes

Stop every app/worker first and keep the archive on an actual private durable
disk. The archive parent must be private mode 0700; the archive is mode 0600.
The command keeps the entire SQLite tool registry archive (including tools),
checks schema and row integrity, refuses non-empty executable tool grants
until the tool registry itself can be migrated, rejects conflicting hosted
records and uses an exclusive workspace lease. It copies BOTH companion
tables in one hosted transaction, verifies all row values and then clears
ONLY migrated local companion rows in a second local transaction. Executable
tool records remain local, not deleted. If interrupted after hosted commit
but before local cleanup, retry checks hosted values before cleaning local
rows. On any conflict, no local rows are removed. Rollback must restore the
full original private SQLite archive before returning to an old local build.

Source: db/companion_import.py, db_cli.py; focused tests/test_companion_import.py
covers original tool retention, private archiving, conflicting target, unsafe
grants, same-file alias, missing source, explicit owner approval, interrupted
retry, and disposable PostgreSQL reconnection.

These tests have been WRITTEN but NOT EXECUTED in this iteration, because the
