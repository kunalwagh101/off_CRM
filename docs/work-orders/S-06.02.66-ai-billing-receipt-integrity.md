# S-06.02.66 — A10 priced model receipts cannot silently become free calls

Status: BACKLOG, test-first build-ahead requested while audit S-06.02.23 is IN_PROGRESS. Branch: develop only. Do not mark DONE until independent and deployed release acceptance.

## User outcome
When a configured paid model reports no usage, zero usage for nonempty work, or invalid usage numbers, the broker must not silently charge USD 0 or lose the response after the provider has been called. It must use a clearly labelled local estimate, retain the durable quota reservation, and refuse the next call when the budget cannot cover it.

## Existing boundaries
- One AI provider transport gate: `offsetx_apollo_builder/ai/broker.py`.
- Usage extraction: `offsetx_apollo_builder/outreach/providers.py::read_usage`.
- Durable, atomic call quota: `offsetx_apollo_builder/ai/quota.py`.
- Existing A11 work `S-06.02.60` already implements atomic reservations, tested in isolated Render; do not replace it.
- No model is given a tool or CRM access. All tests use an offline provider double and disposable quota storage, never real credentials or paid sends.

## Acceptance criteria
1. **Given** a priced provider with a documented token price and a daily USD budget, **when** it reports valid token counts, **then** the actual price is reconciled once, visible as `source=provider`, survives a new ledger instance and prevents the next unaffordable request before transport.
2. **Given** a paid text call with a zero/empty/malformed receipt, **when** nonempty text was sent or returned, **then** both the usage parser and the broker refuse to label its cost as provider-confirmed USD 0; the broker uses a positive clearly labelled local estimate. An invalid receipt cannot throw after transport and strand the API response.
3. **Given** a cost ceiling below the next worst-case reservation, **when** a second call starts on another broker or after restart, **then** it does not call the provider. This holds under a genuine multi-process race and for requests with a cached or invalid usage response.
4. **Given** invalid/corrupt quota persistence, an unpriced model under a USD cap or a provider failure with uncertain billing, **when** a call attempts to start, **then** it fails closed or conservatively charges the reservation, with no automatic resend; exposed errors/logs must not contain secrets.

## Test-first implementation and QA
- First add `tests/test_ai_billing_integrity_a10.py` (and a real broker entry point with priced Mistral model and synthetic response). Run TDD RED on isolated Render; record the expected failures. Do not claim RED is production green.
- Correct receipt validation at the shared `read_usage` and `measure` boundary, not by setting a minimum fake USD charge. Preserve legitimate one-sided zero counts (e.g. request tokens >0, output tokens 0).
- Keep the existing reservation/reconcile transaction. Never rerun the external provider to repair accounting.
- Run focused A10+A11 and cost-ledger tests, `uv run pytest -q` on SQLite and real disposable PostgreSQL, Ruff, frontend, Chromium, security and board verifier; record source-bound Render status.
- Confirm that rollback does not delete or reset the durable quota ledger. Reverting validation knowingly reopens the risk and must not be treated as a safe live rollback until current counters are retained and operations are stopped.

## Outside this slice
Real paid-provider invoices, provider-side hard price caps, unpriced image/audio generation budgets, independent penetration review, production account acceptance and the broader 35-finding A10 audit. Keep those gaps visible. No main/customer deployment.
