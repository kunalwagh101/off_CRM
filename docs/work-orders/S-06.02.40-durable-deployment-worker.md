2. From the real app entry point, create a disposable approved due job. With the browser closed, verify it is processed with the expected receipt/status and exactly one provider-side effect or a controlled uncertain/quarantined outcome.
3. Kill and restart the worker before/after provider submission, simulate database disconnect and concurrent workers. Verify no duplicate effects, bounded retry, visible reference IDs and persisted queue state.
4. Prove clean health/log/restart behaviour, monitoring and rollback; use a durable destination for outstanding outbox/files or refuse production operation until they are durable.
