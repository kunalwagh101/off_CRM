# S-06.02.59 — Cache answers retain their true model and instructions (A13 / D-361)

Status: IN_REVIEW pending exact-source complete QA and release acceptance. Branch: `develop` only.

## User outcome
Changing a selected model, its system instructions, request generation options or expected response format causes a new model run. A cached answer can never be presented as the output of another model.

## Contract and implementation
- Bind an existing cache entry's eligibility to `workspace_id`, `data_class`, `policy`, `task_type`, `provider_id`, **`model_id`**, system-instruction digest, generation-options digest and exact canonical payload.
- Hash raw system instructions; never put them, secrets or customer text in index keys, logs or diagnostics.
- At the single `EgressBroker.call` egress boundary, supply the actual candidate model id and request options plus `expect_json` on **both** cache read and write. Keep existing generation and logging inside that boundary.
- Preserve truthful `usage_source=cache` and provider/model attribution for exact hits; cache hits still pass the original scanner and policy controls.
- Old rows use legacy partitions and must not be selected by changed generation contracts. No database schema migration.

## Test-first acceptance
- **RED:** the previous cache `get` ignored model id; `put` rejected a system-prompt argument; the same model's cached result was reused under different instructions.
- **GREEN:** direct cache isolation tests for changed model/prompt/options and actual `EgressBroker.call` tests across two same-provider models and two system prompts; no duplicate egress on an identical call.
- Full review Docker QA including SQLite, disposable PostgreSQL, security checks, frontend, Chromium and regression suites. Show the exact commit/deploy in evidence.
- Include budget/privacy failure checks. Do not exercise real paid credentials without authorisation.

## Operational notes and rollback
The partition uses cryptographic digests and existing indexed columns, requiring no new table. Existing older cache hits deliberately become misses. This increases model calls until the new cache warms. Rolling back reopens false model attribution; do not deploy a rollback lacking equivalent provenance isolation.

**Release blockers:** independent penetration, real provider/model behaviour, full historical verifier and operator production acceptance. Keep IN_REVIEW until those gates pass.
