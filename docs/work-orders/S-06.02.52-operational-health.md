# S-06.02.52 — Owner operational scheduler health

**Feature:** F-06.02 production reliability / A17. **Status:** IN_REVIEW. **Branch:** develop.

## Real user path
The install owner calls `GET /api/v1/operations/health` with a valid install token or owner session and receives safe health states for email automation, content automation and agent routines across every workspace. Read-only: no credentials, customer records, raw filesystem paths, mail sending or provider calls. The separate public `/health/live` and `/health/ready` remain unchanged to prevent optional automation crashes from causing a restart loop of a healthy web service.

## Accepted behaviour
- No credential is refused 401; ordinary workspace member is refused 403; install owner sees a bounded response.
- Disabled optional scheduler => disabled; enabled + stopped task => degraded with `alert_required=true`; still `/health/ready` 200 if required web stores work.
- Any enabled routine in any workspace makes stopped routine scheduler degraded.
- Config inspection failures => unknown, `inspection_failed`, logged E-reference; never expose exceptions, file paths, key strings or customer data.
- Configured-but-enabled scheduler error => degraded by static `scheduler_error` code, without raw log text.
