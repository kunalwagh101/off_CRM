# Work order — S-06.02.01 generic secret assignment scan

## ID
S-06.02.01 — No secret may enter a model prompt. CHECK-mode defect repair.

## GOAL
Model-visible input must be refused when it contains a generic credential
assignment or credential-shaped field such as api_key, client_secret,
secret_key or api_secret, even when the value does not match a vendor-specific
token prefix.

## FILES
MODIFY:
- tests/test_ai_prompt_secret_scan.py
- offsetx_apollo_builder/ai/scanner.py
- DEFECT_LOG.md
- BUILD_STATE.md
- CHANGELOG.md
- TRACEABILITY.md
- DEMO.md

DO NOT TOUCH:
- provider trust tiers or policy ceilings
- payload allowlist construction
- mailbox unlock policy
- transport API-key injection
- model routing/failover
- redaction behaviour (scanner still blocks; it never repairs and sends)

## TEST
Add parametrized regressions that place these strings in system_prompt and
requires EgressBlocked before provider instantiation:
- api_key=my-private-opaque-value
- client_secret=opaque-client-secret-value
- secret_key=opaque-secret-key-value
- api_secret=opaque-api-secret-value

The values deliberately do not use OpenAI/GitHub/AWS/etc. prefixes. Also build
a FULL-policy unrestricted mapping with each generic credential field name and
require the structural key scan to block it. The tests are about generic secret
shape, not vendor recognition.

## FIX
Extend the existing credential-pattern table with one bounded, case-insensitive
assignment pattern for api key / api secret / client secret / secret key names,
and add those names to the structural secret-field deny-list. Keep the current
block-and-raise behaviour and masked finding output.
