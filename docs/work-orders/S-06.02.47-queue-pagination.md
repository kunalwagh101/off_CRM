# S-06.02.47 — Paginate the Send Queue without changing the sender

**State:** IN_REVIEW; application suites and browser tests not executed. **Branch:** develop only.

## User story
As the campaign owner, I want a bounded, navigable queue, so that I can inspect every queued contact without the browser loading thousands of private contact records.

## Acceptance
- Given a campaign with 211 contacts, when the Queue screen opens, then the API returns at most 100 rows by default and reports the entire matching total.
- Given more than one page, when Previous or Next is selected, then records are stable, nonduplicated and can be inspected on later pages; invalid offset or limit is rejected.
- Given an empty or shrinking queue, when page navigation reloads, then the screen offers a useful empty state or returns to a valid page.
- The **sender itself** retains its full-campaign `send_queue()` contract and is not paginated or allowed to auto-send.

## Implementation
- API: `GET /api/v1/campaigns/{campaign_id}/queue?limit=100&offset=0&view=all` (`limit` 1–200).
- Storage: `OutreachStore.send_queue_view()` scans only control metadata for ordering/counts; fetches name/email/generation metadata for selected page IDs with the existing `send_queue()`, whose sending path stays unchanged.
- UI: Queue state, accessible Previous/Next controls and current range.
- Tests: `tests/test_queue_views.py`; `frontend/src/pages/Queue.test.tsx`.
