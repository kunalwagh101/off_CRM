# Work order — S-05.01.02 selector validation

## ID
S-05.01.02 — Extraction packs as declared data

## Goal
An extraction pack with a malformed CSS record selector or field selector must fail while the registry loads, before any page is processed.

## Files
MODIFY:
- offsetx_apollo_builder/extraction_packs.py
- tests/test_extraction_packs.py
- DEFECT_LOG.md
- BUILD_STATE.md
- CHANGELOG.md
- FEATURE_TREE.md
- TRACEABILITY.md
- DEMO.md

DO NOT TOUCH:
- public URL / robots / SSRF policy
- crawler frontier schema or scheduling
- generic JSON-LD parsing behaviour
- competitor teardown
- discovery storage or dedupe
- AI/LLM paths

## Blast radius
Selector declarations are created only by:
- ExtractionPack.from_data(record_selector)
- ExtractionRule.from_data(field selector)

They are consumed only by:
- ScraplingPageParser._people_from_pack()
- ScraplingPageParser._extract_rule()

No public API signature or persisted database schema changes.

## Interfaces
Existing JSON contract remains unchanged:
- pack.record_selector: string
- fields.<name>.selector: string
- mode: text | attr
- attribute: allow-listed attribute for attr mode

## RED tests
Add registry-load tests proving:
1. malformed record selector such as `div[` raises ExtractionPackError;
2. malformed field selector such as `.name[` raises ExtractionPackError;
3. failure occurs in ExtractionPackRegistry.from_data(), before parser/page creation;
4. valid selectors used by existing packs still load.

## GREEN implementation
Use the already-declared Scrapling dependency to parse-check CSS selector syntax at registry load. Do not add another CSS parser dependency or invent a partial CSS grammar.

The validation helper must:
- preserve the existing size/non-empty checks;
- reject malformed selector syntax with a precise ExtractionPackError naming the selector;
- reject selector pseudo-elements that conflict with the parser's own text/attribute extraction suffixes;
- perform no network access and execute no user code.
