# Work order — S-12.01.03 the video director uses the product

## ID
S-12.01.03 — The video director uses the product. Board: BACKLOG (pullable:
its dependency `S-12.01.02` is DONE). Fixes `D-81`. Size M. Epic E-12.

## GOAL
A directed video for a campaign linked to a product speaks in the product's
voice — and nothing the owner typed travels outside the classified request
fields. Every director call's egress log shows everything that left, the
system prompt included.

## BLAST RADIUS / CONSUMERS
- `offsetx_apollo_builder/video/director.py` — `build_prompt(style=)` appends
  `House style: <owner text>` to the **system prompt**; `direct(...)` calls
  `ask(system_prompt=build_prompt(style=style), topic=subject)`.
- `offsetx_apollo_builder/api/app.py` — `video_director(**kwargs)` inside the
  video engine factory sends `EgressRequest(task_type="video_direction",
  data_class=DataClass.PUBLIC, instructions=topic, public_text=topic)` with the
  system prompt beside it.
- `offsetx_apollo_builder/ai/broker.py` `_log(...)` and
  `offsetx_apollo_builder/ai/log.py` (`ai_egress_log`, `record(...)`): the log
  keeps the payload, not the system prompt.
- The egress wall: `tests/test_ai_egress_wall.py` (34 cases) and rule 1 in
  `AGENTS.md` — the broker stays the only gate.

## ROOT CAUSE (`D-81`)
The system prompt is outside the payload: the payload builder never classifies
it, the policy never governs it, and the log never records it. Owner text put
there reaches any tier a `public` request may reach — tier C and D included —
and leaves no trace.

## DESIGN — follow what `S-12.01.02` did for posts
The post pipeline is the pattern (`_pipeline` in `api/app.py`): the request is
`DataClass.CAMPAIGN` when owner material is present, `PUBLIC` otherwise, and
the system prompt is a fixed, code-authored string.

1. **The system prompt holds no owner text.** `build_prompt()` loses its
   `style` argument; it returns the declared shapes only, a constant.
2. **Owner material travels classified.** When the video's campaign is linked
   to a product — `GtmStore.product_for_campaign(campaign_id, workspace_id)` —
   or the owner typed a house style: the product's one-liner goes in
   `positioning_line`, and the rest of the product plus the house style in
   `campaign_notes`. Reuse `gtm/strategy.py::product_lines()` for the product
   text rather than writing a second formatter. The request becomes
   `DataClass.CAMPAIGN`. The topic stays `public_text`.
3. **With no product and no style**, nothing changes: `PUBLIC`, topic only.
4. **The log shows the system prompt.** Add a `system_prompt` column to
   `ai_egress_log` (`database.add_column_if_missing`, as `gtm/store.py` does
   for its own schema changes), pass it from `broker._log`, and cap it as
   `payload_json` is capped. This is for every call, not only the director:
   the criterion is "everything that left".

## TEST (write it first, watch it fail)
1. A video campaign linked to a product, directed with a fake model call (use
   `tests/broker_fakes.py::fake_model_calls`, as the GTM tests do): the request
   the fake sees is `campaign` class; its `positioning_line` is the product's
   one-liner; the house style is in `campaign_notes`; the system prompt
   contains neither the product text nor the style.
2. A policy that forbids campaign material on the only provider: the call is
   refused, never downgraded to `public`.
3. After any director call: the egress log row's `system_prompt` equals what
   was sent.
4. No product and no style: the request is `public`, exactly as today.
