# S-06.02.49 — Focus the Send Queue on a specific action

**State:** IN_REVIEW, browser and full suites unrun.

## User story
As a campaign owner I want to see All, Approved and due, Needs approval, and Replied cohorts individually, so that I can work through a campaign without mistaking a long list for a complete review.

## Acceptance
- Given each cohort, when the view is selected, then only matching contacts appear; the count, pagination and route match the selected view.
- Given a view change, when loading completes, then the page resets to zero and the real global stat counts remain visible.
- Given a cohort with no members, then the empty state explains that view instead of suggesting the campaign has no contacts.
- No Approve/Send action is implied by changing the view; live Gmail sends continue to require the existing explicit human confirmation.

## Implementation
The API validates `view=all|ready|approval|replied`. The store classifies each lightweight queue row before page slicing and fetches the selected detail rows only. UI offers a labelled select box, view count, and independent queue page controls; tests cover API invalid values and accessible view selection.

## Required gates
Python API/store suite, frontend Vitest+build, Chromium interaction across filters, and full board verifier. No external services, database migrations or extra privileges. No production release claim until verification.
