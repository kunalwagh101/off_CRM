# Work order — S-06.03.04 Hosted PostgreSQL backup and recovery

## Goal
An owner-controlled nightly encrypted export of the *actual hosted PostgreSQL* lives outside the database/service. The install owner can download the backup and restore it into a disposable empty PostgreSQL database with reconciled table counts. Do not confuse a local SQLite ZIP with a hosted database backup.

## Read and preserve
`AGENTS.md`, `docs/architecture/HOSTED_STORAGE.md`, `offsetx_apollo_builder/db_cli.py`, `offsetx_apollo_builder/api/production_runtime.py`, `offsetx_apollo_builder/outreach/backup.py`, `offsetx_apollo_builder/db/connection.py`, `tests/test_hosted_storage.py`, `tests/test_crm_hosted.py`. The existing local encrypted backup path must remain intact, and hosted local-backup refusals remain until a real PostgreSQL export/restore exists.

## Readiness and external decision
`S-06.03.03` is DONE. **Q-29 is open**: owner-approved separate durable backup destination, credentials/permission scope, rotation and retention, and unlock-key custody. Do not choose a backup service silently or write backups to Render's ephemeral filesystem or the same database. This work order is preparation only until Q-29 is answered and the real PostgreSQL runner/restore target is available.

## Acceptance — red before green
1. With a real hosted database containing CRM, logins, encrypted provider settings and audit events, export a consistent database snapshot, envelope-encrypt it with a separately managed key, and store it at the authorised offsite destination. Re-run after the process/container is destroyed; the export remains accessible outside the app and primary database.
2. Delete or isolate the test database and restore the export into a new empty PostgreSQL database. Reconcile per-table row counts and spot-check integrity, ownership, key validity and next-sequence values. Never restore over active production state by accident; explicit install-owner approval and a unique destination are required.
3. Simulate encryption-key mismatch, failed upload, partial export, lost remote access, checksum mismatch and failed restore. The job emits a secret-safe failure reference; it does not report success or overwrite the last valid backup. Bound retries, storage cost, data size and schedule concurrency. Owner download returns only ciphertext.

## Rollback, gates
No automatic deletion of a good historical backup. Any rollback must keep the previous verified export readable and turn off scheduling safely. Tests: focused export/restore PostgreSQL integration, existing local-backup regression, full `uv run pytest -q`, `uv run python scripts/verify_board.py` plus actual remote destination + restore demonstration. No DONE claim without real target, runner, owner download and recovery evidence.
