## Delivered in code on develop
- `gtm/service.py`: new optional expert search and winner-reference readers. The planner fetches at most four expert excerpts, caps each at 900 characters, includes source labels within the existing 4,000-character campaign-notes limit, and passes the winning template in `template_text`, never in unclassified instructions/system prompt. It records the reference count in stored plan notes and warns if a thin provider policy prevented the references being sent. The no-reference case keeps the earlier fields.
- `api/app.py`: resolves the workspace's template winner using `ai_context.reference_for_models(workspace_id)` and the existing owner-side expert chunks search. The expert_chunks table currently lacks workspace IDs; to prevent tenant leaks, the imported owner corpus is **not offered to client workspaces**. This limits availability until tenant-scoped expert storage is implemented.
- `ai/evals.py`: EvalCase carries campaign_notes and its template field to the broker unchanged; `without_references` removes only these two fields from a controlled variant. The suite uses the actual `gtm.strategy.build_prompt()`. Model eval calls now also supply that system prompt to the broker (previously blank). Pure GTM checks reject unregistered/repeated channels and daily volumes above fixture capacities.
- `ai/eval_cli.py`: `offsetx-evals run --suite gtm_plan --ablate references` evaluates every connected model twice and prints both scores, with the doubled approximate call count shown before starting. A dry run spends nothing. It refuses to promote a champion when fewer than 30 **explicitly judged real cases** exist or when any synthetic/unverified cases remain.
- `config/evals.yaml` and packaged copy: three explicitly labeled *synthetic* GTM contract starter cases, **not** 30 fabricated owner outcomes.

## 2026-10-13 controlled A/B correction (D-268)
A source review found that `without_references` deleted all `campaign_notes`, not only expert citations. Real GTM drafts also use this field for product and revision facts, so the reference/no-reference comparison could change both reference access and essential campaign context.

`EvalCase` now stores baseline `campaign_notes` separately from `expert_reference_notes` and assembles them in the same classified field for provider requests. Reference ablation drops only expert reference notes and the winning `template_text`, leaving original product/campaign notes unchanged. Both the config and packaged eval suites move their three synthetic expert excerpts to `expert_reference_notes`; with-reference payloads remain equivalent to the previous fixture text. A regression case explicitly checks non-reference product notes are preserved.

**Compatibility:** any external GTM eval YAML that previously put expert excerpts in `campaign_notes` must move them to `expert_reference_notes` for a meaningful ablation; `campaign_notes` now always means baseline context. `template_text` remains a removable winner reference in the GTM suite.
