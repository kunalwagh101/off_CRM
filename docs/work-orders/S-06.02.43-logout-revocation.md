# S-06.02.43 — Logout makes copied browser cookies unusable (audit A06 / D-273)

**Status: IN_REVIEW, no full API/Postgres/runner proof.** Role: security/backend engineer. Branch: develop.

## Gap
Deleting a browser cookie does not revoke a copied signed bearer value. `WorkspaceAuthStore.verify` previously checked signature, expiry and account session version only. A stolen cookie could be replayed after logout.

## Acceptance
- Logout invalidates that exact cookie before returning authenticated=false; other devices of the same account continue to work.
- Replay is refused by the same server, a new process after restart, or another process using the hosted database. Revocation is stored as token SHA-256 only, with expiry, not raw token.
- Signature, expiry, account-disable/password-change and workspace checks remain in place. Malformed/absent cookies are safe no-ops. If storage is unavailable, logout must not report success.
- Old hosted DB schema upgrades atomically; fresh SQLite installs create the table. Rollback instructions explain that an old application version without the revocation check cannot safely accept the same session-signing key.

## Implementation
`api/auth.py` adds one additive hosted schema step and SQLite table, token digest lookup in verification, and durable one-session revocation with expired-record cleanup on logout. `api/app.py` revokes the request cookie before deletion. `tests/test_api_auth.py` covers copied-cookie replay after restart and isolation from another valid session. The stateless `DemoSessionAuth` helper is test/legacy-only; the real API issues and verifies via `WorkspaceAuthStore`.

Never silently restore a revoked cookie's validity.
