Owner selection: 2026-10-12, one scoped feature. Kanban WIP = 2 with S-06.02.23 still active; the current request expressly authorises another feature. Do not change that audit's acceptance or claim it DONE.

## Fault and user outcome
A34/D-122: a real 60-frame two-second Colour export of only 3,773 bytes was refused by the fixed 4,096-byte threshold. The file size is not proof of absent encoded samples. The user should see a completed valid export, while empty/metadata-only/corrupt exports remain refused.

## Scope and consumers
Only `offsetx_apollo_builder/video/gates.py` and `tests/test_video_gates.py` plus a small independently encoded test file. The caller contract and gate names stay unchanged. Check the UI export API and pipeline callers before editing; do not change generic MP4 or the frontend encoder.

## Red/green and acceptance
1. A real VP9/WebM fixture independently produced with ffmpeg (2 s, 30 fps, 360x640, 60 video frames, 2,150 bytes) fails the old size-only check. This was reproduced offline.
2. Replace the size-only refusal for *small WebM* with a bounded WebM element scan that confirms at least two nonempty video blocks belonging to a declared video track. Reject malformed/container-only and audio-only samples. Leave the usual 4096-byte gate for formats without independent evidence.
3. Keep the full existing checks for header, required tracks, duration, aspect, media type and deduplication. Add named regression cases for pass, empty and malformed inputs. No codec decoding is claimed by the lightweight gate; use the independent ffprobe check on the fixture to verify actual decodability.

## 2026-10-12 implementation checkpoint

The original 4096-byte predicate was tested with an independently encoded two-second VP9/60-frame clip, 360x640, 2,150 bytes: legacy acceptance was false. `ffprobe` independently confirmed duration, codec and decoded frame count. A local standalone version of the EBML sample-block predicate accepted the clip and rejected four invalid/empty/truncated byte sequences.

`offsetx_apollo_builder/video/gates.py` now grants a narrow exception only to small WebM files containing at least two nonempty encoded sample blocks on a declared video track. The ordinary header, dimensions, duration, audio, MIME and hash gates remain. An actual test fixture and named regression tests have been committed. Source logic and isolated parser checks were exercised; **full repo tests and the browser export have not run** because the private repo cannot be cloned here and CI runners have failed before allocation. See `docs/evidence/S-06.02.39-validation.md`.

Status: **IN_REVIEW**, not DONE and not a verified deployment. Rollback is a Git revert of the implementation commit; no data migration is involved.
