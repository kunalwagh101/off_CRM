## GOAL
With `OFFSETX_DATABASE_URL` set, every campaign, contact, draft, send, reply and
delivery job lives in that database and survives the data folder being wiped,
on SQLite and on any PostgreSQL 13 or newer. An existing SQLite CRM is copied
across with every table's count reconciled, and copied back the same way. With
no `OFFSETX_DATABASE_URL`, nothing changes.

## FIXED — decided, do not re-decide
1. **One seam.** `OutreachStore(target)` takes a SQLite path *or* a PostgreSQL
   URL and opens it with `db.open_database(target)`. It exposes
   `store.backend` (`"sqlite"` / `"postgres"`), `store.database`,
   `store.integrity_error` and `store.path` (`None` on PostgreSQL). No other
   module opens the CRM itself. *(Built 2026-10-03: on SQLite the store still
   opens its file itself, as FIXED 2 needs — `test_security_audit.py` reads
   `__init__` for `isolation_level=None` and `GuardedConnection`. So
   `store.database` is the `PostgresDatabase` there and `None` on SQLite, and
   on PostgreSQL `store.connection` is that same object.)*
2. **SQLite behaves exactly as today.** Same pragmas (`foreign_keys`, WAL,
   `synchronous=NORMAL`, `busy_timeout`), same `user_version`, same
   `_migrate_legacy_schema`, same FTS5 table. Every existing test passes
   untouched through it.
3. **DDL widths (`DD-71`).** In `outreach/schema.py`, `INTEGER` becomes
   `BIGINT` and `REAL` becomes `DOUBLE PRECISION`. SQLite gives both the same
   affinity as before, and an existing SQLite file is not touched
   (`CREATE TABLE IF NOT EXISTS`). No regex rewrites SQL at run time.
4. **Schema on PostgreSQL.** `db.schema.ensure_schema(database, "crm", steps)`;
   step 1 runs `SCHEMA_SQL` then `POST_MIGRATION_SQL`. No legacy migration (no
   old PostgreSQL CRM exists). No FTS5: `fts_enabled` is `False` and the
   existing non-FTS search path is used. A later `SCHEMA_VERSION` bump must add
   a PostgreSQL step too; say so in a comment at `SCHEMA_VERSION`.
5. **Transactions.** SQLite keeps today's `BEGIN` / `BEGIN IMMEDIATE` /
   savepoint code. PostgreSQL uses `store.database.transaction()` (psycopg
   nests it as a savepoint). *(Built 2026-10-03: no depth counter after all —
   `PostgresDatabase.transaction` already nests and already holds its lock for
   the whole transaction, so the store adds only the advisory lock.)*
6. **`immediate=True` on PostgreSQL (`DD-72`)** takes
   `pg_advisory_xact_lock(7103206302)` first. It is what `BEGIN IMMEDIATE`
   gives SQLite: one writer at a time *across processes* — the web app and
   `offsetx-email-worker` both claim delivery jobs.
7. **Search ignores case on both (`DD-73`).** Every `col LIKE ? ESCAPE '\'` in
   the store becomes `lower(col) LIKE lower(?) ESCAPE '\'` (lines 519, 675,
   919, 2243 at `f8574ef`). SQLite's `LIKE` ignores ASCII case and
   PostgreSQL's does not, so "acme" silently stopped finding "Acme Corp".
8. **Upserts.** The four `INSERT OR IGNORE` / `INSERT OR REPLACE` become
   `INSERT … ON CONFLICT (…) DO NOTHING` / `DO UPDATE SET …` (SQLite 3.45 here).
   Check first that nothing hangs off an `INSERT OR REPLACE` row by a cascading
   foreign key: `REPLACE` deletes the old row, `DO UPDATE` does not.
9. **Errors by class, never message.** `sqlite3.IntegrityError` →
   `store.integrity_error`; `sqlite3.OperationalError` around a statement →
   the backend's error via `store.database`. `sqlite_master` / `PRAGMA
   table_info` → `store.database.columns(table)`.
10. **Which target the app gives the CRM.** One function,
    `data_paths.crm_target(settings)`: `OFFSETX_DATABASE_URL` when set, else
    `OFFSETX_OUTREACH_DB`. Every constructor uses it: `api/app.py` (589, 730),
    `email_worker_cli.py:94`, `outreach_cli.py:135`, `notebook_cli.py:65`.
    An explicit `--db` / `--database` still wins, as today.
11. **A local CRM left behind (`D-210`'s rule).** Hosted, and the
    `OFFSETX_OUTREACH_DB` file holds any CRM row → `create_app` refuses with a
    sentence naming `offsetx-db import-crm --yes` and `--skip`. `--skip` is
    remembered exactly as `hosted_import.skip_local` remembers it. On Render's
    free plan the file does not exist, so nothing is refused there.
12. **Local backup** stays refused while hosted (already so for the egress
    log). `OutreachEngine` backup on PostgreSQL raises a sentence; it never
    calls `sqlite3` `backup`.
13. **Copy tool.** `outreach/store_copy.py`: `copy_crm(source, destination) ->
    CrmCopyReport`, `CrmCopyError`. Opens both through `OutreachStore`,
    refuses a destination holding any CRM row ("already holds"), copies
    parents before children in one destination transaction, never writes the
    source, then compares `table_counts()` on both. `table_counts()` lists
    every CRM table and excludes `offcrm_schema` and the FTS5 tables (rebuilt
    on SQLite after `expert_chunks` lands). CLI: `offsetx-db copy-crm --from
    X --to Y` and `offsetx-db import-crm --yes|--skip`.
