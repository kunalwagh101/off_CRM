# S-06.02.68 — Isolate workspace-owned video projects, media, renders and reviews

Status: BACKLOG, security build-ahead while S-06.02.23 production audit remains IN_PROGRESS. Develop only.

## Problem and existing design

VideoStore already writes a workspace_id on video_projects, video_media, video_renders and video_reviews. The API resolves a real authenticated workspace in _video(request). However VideoEditorEngine and direct /video-media/{id}/file and /video-renders/{id}/file endpoints retrieve records by global IDs, and campaign lists and queue/summary list records from other workspaces. With Q-27 global CRM campaign tenancy undecided, shared campaign IDs cannot be used as video ownership proof. This is an A05 cross-workspace disclosure and mutation defect, not permission to migrate CRM records.

## Acceptance
- Two real authenticated workspaces share a synthetic image campaign ID. Each can create own video project and list only its own projects. Another workspace's project ID is treated as absent on read, edit, history, undo, delete, review, render list, queue and upload; no foreign version or review change.
- Imported video media and renders are owned by the workspace that stored them. Direct file URLs, metadata lists, transcription, placement and auto-assembly cannot read or reuse another workspace's media; another workspace's render file does not leak bytes.
- Review queues, approved renders and summary use SQL-level owner filtering *before* LIMIT; unknown workspace IDs get no data. Same-workspace operations remain working, including owner/admin local install and legacy local rows.
- Missing/foreign resources return a bounded 404, not a 500, with no file paths, bytes, submitted text or foreign workspace names. No provider or external send is used to prove this.
- Tests run first against real API cookie sessions and synthetic assets (RED), then focused GREEN, SQLite and real disposable PostgreSQL, frontend/Chromium/security/board checks through isolated Render. No main/customer deploy.

## Implementation boundaries

Implement a private _owned_project/_owned_media resolver in VideoEditorEngine and enforce before state changes. Scope list queries to workspace in VideoStore instead of filtering after pagination; add ownership to the two direct file API endpoints. Keep schema, existing workspace_id, CRM campaign ownership and provider/policy rules unchanged. Preserve authenticated local owner access to their own local rows.
