# Work order — S-04.01.01 exact companion memory scope

## ID
S-04.01.01 — Companions: persisted agent profiles. CHECK-mode defect repair.

## GOAL
A run started under a companion must see approved memory from that companion's
exact scope only. Production global memory must not be silently merged in.

## ROOT CAUSE
`CompanionRegistry.start()` passes `scope=<companion scope>` to the production
CRM memory store. `OutreachStore.search_memory_items()` historically interprets
any scoped query as `global OR requested scope`. The existing companion unit
fixture implements exact-scope semantics, so it does not reproduce production.

## BLAST RADIUS
Known direct production consumers:
- `agent/companions.py` — requires exact scope.
- `api/app.py` memory-list/search routes — retain existing global+scope
  behaviour unless they explicitly opt out.
- `outreach/store.py` — shared implementation.

The shared method therefore keeps its current behaviour by default and receives
one explicit opt-out used only by companions.

## TEST
Use the real `OutreachStore`, not the fake memory fixture:
1. create a companion;
2. write one approved item to `global`;
3. write one approved item to the companion scope;
4. start the companion;
5. assert only the companion-scoped item is returned.

The test must fail on the pre-fix implementation because the production store
returns both rows.

## FIX
Add `include_global: bool = True` to `search_memory_items()`. Preserve the
current default for every existing caller. `CompanionRegistry.start()` passes
`include_global=False`.
