# S-06.02.36 — Explicit owner-login confirmation

Protect the existing authenticated workspace-creation API against accidental creation of another install-owner login. Keep old accounts and local bootstrap behaviour unchanged. Add opt-in confirmation on requests for workspace `local`, reject ambiguous confirmation for other workspaces, and test the endpoint's security boundary before modifying implementation. Run the full test suite and board verifier; until results exist, keep in review.

## 2026-10-13 implementation checkpoint
The API request accepts a strict JSON boolean `confirm_install_owner`. A new `local` workspace login requires true, and supplying true for any other workspace is refused. Old logins and internal bootstrap are unaffected. Two TestClient regression cases (including non-admin refusal, coercion refusal and actual local login) were committed ahead of implementation, but full suite and live API proof have not executed. Evidence: `docs/evidence/S-06.02.36-validation.md`. IN_REVIEW, not DONE.
