# S-06.02.37 — Skip navigation keeps the current screen

## Task and user-visible outcome
Fix D-239. The existing <a href="#main-content"> is a real skip link, but React uses the location hash as its route. The native anchor click changes the hash to `#main-content`; `currentPage()` interprets that as Dashboard and wrongly changes screens. Keep the current route and focus the existing main without new routing or abstractions.

## Code and consumers
- `frontend/src/App.tsx`: existing `focusMainContent()`, `AuthenticatedApp`, `currentPage()` and `hashchange` handler. The link and page navigation share the focus function. Do not change normal route navigation or `focusMainContent()`'s scroll behaviour.
- `frontend/src/components.test.tsx`: existing focus tests; add a regression proving default navigation prevented on both pointer activation and the click keyboard activation uses.
- `tests/test_frontend_accessibility_contract.py`: keep the actual link href and focus target for assistive technologies.
- Preserve `S-06.02.25` focus-on-navigation and sticky top-of-screen behaviour.

## Test first
- Given hash `#settings`, activating Skip using the click event (keyboard Enter triggers a click as well) prevents native hash navigation; main is focused and scrolled to top.
- Given hash `#contacts`, pointer activation has identical behaviour.
- Existing navigation via sidebar still changes route and focuses newly mounted main.
- Accessibility contract still contains genuine `href="#main-content"` and `tabIndex={-1}` target.

## Implementation
Use one bounded exported `skipToMainContent(event)` event handler in App.tsx to `preventDefault()` then invoke the existing `focusMainContent()`. Do not use history manipulation; this leaves browser back/forward and the current page hash intact.
