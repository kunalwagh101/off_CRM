# S-06.02.34 — Connectors usage and available provider balance (2026-10-13)

**Status: IN_REVIEW, not DONE, not deployed.**

## Implemented
- `ai/registry.py` and source/packaged `providers.yaml`: every provider declares `usage_report` as `none`, `balance_endpoint` or `rate_limit_headers`. OpenRouter and DeepSeek have documented balance endpoints; OpenAI, Groq and Anthropic have rate-limit headers; NVIDIA and others have no supported remaining figure in this build.
- `ai/provider_usage.py`: bounded, explicit HTTPS GET to hardcoded OpenRouter or DeepSeek API using only the current workspace's saved bearer key. Redirects and environment proxies refused, 16-KiB response limit, finite nonnegative decimal validation, source and timestamp included; OpenRouter's per-key spend cap is **not** represented as an account balance. No user CRM data, prompt or model-call payload is sent.
- `api/app.py`: POST /api/v1/ai/providers/{id}/balance consults the authenticated workspace's key. Non-connected balance-capable providers fail 409. Unsupported providers return supported=false and a truthful reason; errors do not disclose provider responses or credentials.
- `frontend/src/pages/Connectors.tsx`, `types.ts`: all connected providers show their counted local daily call total, with/without cap; balance-capable providers offer an explicit Check provider balance button and a timestamped response; changing a key invalidates the old reading. Unsupported or headers-only reporting is labeled accurately rather than inventing a number.
