# Work order — S-06.02.57 A09 keyboard activation safety

## Purpose
An agent can press Enter in a focused textarea, contenteditable editor or standalone input. Sites attach their own keydown handlers, including irreversible submit operations. The current DOM probe returns an empty role for these fields and Page.press dispatches the key unconditionally. A custom or non-English control can also evade the English-only label heuristic. No model output or untrusted page text may grant approval.

## Definition of Ready
- Direct owner instruction on 2026-11-03 authorises a new remediation with S-06.02.23 audit still in progress. WIP <=2.
- Existing S-11.03.03 keyboard gate, Page and RunLoop are reused. No separate AI broker or model tool.
- No external credential, new store, provider, schema or migration needed. The controlled browser exercise uses disposable local data pages only.

## Test first
1. Add deterministic Page.press tests for focus probe returning unknown, foreign/custom and missing form. Assert no Input.dispatchKeyEvent before human confirmation; navigation keys still pass.
2. Add real Chromium tests in tests/test_browser_agent.py using controlled data: forms with textarea, contenteditable, standalone input and a custom non-English button. The page has a JavaScript Enter listener that changes only local text; without confirmation it must stay UNSENT.
3. Run early tests on isolated Render QA to observe RED before fixing source, then change only Page.press intent detection/fail-closed policy and rerun GREEN.
4. Run full SQLite, PostgreSQL, frontend, real Chromium, static/security and board gates on the exact resulting commit. Record what is verified, skipped or blocked. No production deploy.

## Acceptance and limits
Safe navigation-key behaviour is preserved. Explicit trusted confirmation can dispatch one Enter; a model still cannot set confirmed=true through the closed action schema. This work blocks a keyboard path but does not automatically prove all click paths, post-navigation approval binding, arbitrary script-controlled effects or independent penetration. Keep A09 and wider audit open until the original full acceptance is verified.

## Rollback
Revert the guarded Enter change only after another input boundary has been proven to stop custom handlers. No database migration or customer content is touched. Never roll this back silently into a production deployment.
