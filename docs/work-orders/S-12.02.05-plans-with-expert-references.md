# Work order — S-12.02.05 the brain drafts against the expert corpus and the owner's winners

## GOAL
When a plan is drafted, the model also sees reference material — the imported
expert library and the owner's judged winning template — in classified request
fields. An eval run scores the brain with and without that material and says
plainly when it has too few cases to trust.

## BLAST RADIUS / CONSUMERS
- `offsetx_apollo_builder/gtm/service.py` `GtmService.draft_plan` (and
  `revise_plan`, which calls it): builds `fields = request_fields(product,
  request, envelope)` and calls `self.ask(system_prompt=build_prompt(),
  task_type="gtm_plan", **fields)`.
- `offsetx_apollo_builder/gtm/strategy.py::request_fields` — decides which
  `EgressRequest` field each piece travels in; its docstring states the rule
  (DD-41): product text in `positioning_line` and `campaign_notes`, never in
  `instructions`.
- The references' sources: `OutreachStore.search_expert_chunks(query, limit=4)`
  (the library the Settings screen imports, table `expert_chunks`), and
  `ContextLayer.reference_for_models(workspace_id)` in `ai/context.py` (the
  judged winning template, one line).
- Evals: `config/evals.yaml` (deterministic checks only — no model judges),
  `ai/evals.py` (`EvalCase`), `ai/eval_cli.py` (`offsetx-evals`), and the
  scoreboard `ai/scoreboard.py`. **There is no `gtm_plan` suite yet.**

## DESIGN
1. **Where references travel.** Reference text is campaign material: the
   winning template in `template_text`, the expert excerpts appended to
   `campaign_notes` under a heading that marks them as references, not
   instructions. Nothing goes in `instructions` or the system prompt (DD-41,
   and the reason for `D-81`). The data policy then governs them like any
   campaign material — at `minimal`, they do not leave.
2. **Which excerpts.** `search_expert_chunks` with a query built from the
   plan's goal and the product's audience and problem; at most 4 excerpts,
   each capped (reuse the email expert's cap in `outreach/email_expert.py`
   rather than inventing a number).
3. **Saying so.** The stored plan's notes say which references it saw ("drafted
   with 3 expert excerpts and your winning template") or that there were none.
4. **The eval suite.** Add `gtm_plan` to `config/evals.yaml`, in the same form
   as the other suites: `task_type: gtm_plan`, `data_class: campaign`, the
   brain's real system prompt from `gtm/strategy.py::build_prompt()`, and
   deterministic checks that `parse_plan` can decide — the reply parses, every
   channel is a declared one, the numbers fit the envelope.
5. **With and without.** `offsetx-evals run gtm_plan --ablate references` runs
   each case twice, once with the reference fields emptied, and reports both
   scores. `EvalCase` gains the reference fields it needs, read from the case
   the way `positioning_line` already is.
6. **Too few cases.** With fewer than 30 cases the comparison prints that no
   verdict is trustworthy yet, and says how many more are needed. Thirty is
   the number `config/evals.yaml`'s own header gives.

   "no verdict is trustworthy yet" line; on 30 cases the line is absent.
