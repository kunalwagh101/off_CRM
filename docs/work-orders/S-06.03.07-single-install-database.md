# S-06.03.07 — One hosted database belongs to one installation

Owner decision 2026-11-06: independent installs must not share a hosted database. A stable, non-secret UUID in OFFSETX_INSTALL_ID identifies one logical installation across restarts and replicas; a new independent install uses a new UUID and database. Never generate a replacement on ephemeral disk at startup.

T-06.03.07.a: add an atomic install claim to the existing hosted document store. Reject absent/invalid identity before binding, accept repeated same-identity starts, refuse different or malformed stored ownership without overwriting it. T-06.03.07.b: enforce the claim before app/bootstrap/local-migration decisions; document the required deployment setting and explicit recovery procedure. No customer database mutation or claim transfer is executed in this session. T-06.03.07.c: test two separately opened stores and a two-writer race with one winner, process/restart persistence, real PostgreSQL and both missing/invalid identities. Existing hosted tests receive deterministic per-test install UUIDs; missing-identity tests delete that setting explicitly. Test data never implies real customer ownership.

Migration: existing hosted installs must set a stable UUID before running this release. Their first authenticated bootstrap binds the existing database to that declared logical installation; it does not assign or move CRM customer records. Reuse that setting on restart/recovery replicas. To move installations, restore to a new independently verified database rather than edit ownership. Rollback keeps the claim document and UUID for a future forward restart; no data is deleted. Unknown claims fail closed. Production half-hosted refusal and offsite recovery remain separate gates.

Scope: storage placement/ownership only. This does not grant access to another customer workspace or authorize paid infrastructure.
