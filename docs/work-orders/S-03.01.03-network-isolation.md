# S-03.01.03 — Browser network isolation

Status: BACKLOG; no production access or full validation claim.

## User outcome
No request from the browser runtime can reach private, loopback, reserved, link-local or metadata addresses, including redirects and background requests. Public browsing remains available subject to the existing domain policy.

## Read before editing
`AGENTS.md`, `DEFINITION_OF_DONE.md`, `browser/policy.py`, `browser/guard.py`, `browser/box.py`, `browser/page.py`, `tests/test_browser_agent.py` and `tests/test_browser_box.py`. Audit A07 and D-266 are the source.

## Requirements and tests
- Test a real browser inside the supported container with controlled public and non-public destination fixtures. For prohibited destinations, assert **zero server-side connections**, not just a denied policy result.
- Repeat the same checks for attended/unattended browsing, navigation, redirects, subresources and new tabs. Deny when the network identity cannot be verified.
- Prove permitted public requests still work. Preserve current domain allow-lists and the browser's no-host-filesystem contract.

Do not treat a hostname-only check as sufficient: the actual network boundary must apply independently of application decisions. Avoid extra network privileges, secret logging or fake provider success.

## Commands and release gate
```bash
uv run pytest tests/test_browser_agent.py tests/test_browser_box.py -q
uv run pytest -q
uv run python scripts/verify_board.py
```
Run real browser and container integration checks, with evidence that forbidden connections were not made. CI/browser and container access are currently unverified. Keep BACKLOG until Definition of Ready holds, and IN_REVIEW until all proof gates pass. No data migration. If rollback is needed, disable the affected browsing capability rather than exposing private network access.
