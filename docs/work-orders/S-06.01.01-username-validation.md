# Work order — S-06.01.01 workspace username validation

## ID
S-06.01.01 — Workspaces with their own keys and logins. CHECK-mode defect repair.

## GOAL
Normal one-line usernames must be accepted, while NUL/CR/LF characters remain
forbidden.

## ROOT CAUSE
The compiled regex uses a raw string with double-escaped control sequences:
`r"^[^\\x00\\r\\n]{1,100}$"`. Inside the regex character class this
forbids ordinary literal characters rather than the intended controls.

## FILES
MODIFY:
- tests/test_workspace_isolation.py
- offsetx_apollo_builder/api/auth.py
- DEFECT_LOG.md
- BUILD_STATE.md
- CHANGELOG.md
- TRACEABILITY.md

DO NOT TOUCH:
- password hashing parameters
- session signing/versioning
- workspace-id rules
- API response contracts
- account uniqueness rules

## TEST
Prove representative normal usernames containing r, n, x and 0 can be created
and authenticated. Separately prove an embedded newline and NUL are refused.

## FIX
Use the intended regex control escapes:
`r"^[^\x00\r\n]{1,100}$"`.
